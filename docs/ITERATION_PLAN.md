## 零、结论先说

上一轮把「量得出来、改坏了抓得到」做成了（剖析器、无头渲染器、截图回归），之后两批 three.js 移植又把渲染面铺得很宽。
渲染已经不是瓶颈。这一轮的三件事：

1. **让 CI 真的跑起来。** 上一轮一直写着「CI 有了、只是没在 remote 上跑过」，这次一查，
   **`.github/workflows/ci.yml` 根本不在仓库里**；照现状推上去 fmt 那关也必红（267 个文件没格式化）。
   这是成本最低、风险最大的一项：Linux 上编不编得过，一次都没验过。
2. **导航寻路**——剩下唯一一个「做不了某类游戏」的硬缺口（NPC、塔防、RTS 都卡在它上面）。
3. **实例化**——大量相同物体现在每个都是一个场景节点，CPU 那头按节点付钱。

手柄、根运动在上一轮末尾已经补上（见 ROADMAP 三），不再列。

## 二、方案

### C · CI（先做）

| 编号 | 内容 | 算完的标准 |
|---|---|---|
| C1 | 按默认配置 `cargo fmt --all` 一次（试过放宽行宽，改动只会更多，见「依据」） | `cargo fmt --all --check` 通过 |
| C2 | 推一次，看 Linux 红在哪 | 两个平台测试全绿。预计会撞：大小写敏感的路径（例子里引用 `examples/threejs/...` 的文件名）、`\\` 路径分隔符、Windows 专用的 `cfg`、`#[ignore]` 之外还要显卡的测试 |
| C3 | 截图回归进 CI（可选） | Linux 上用 lavapipe（Mesa 软件 Vulkan）跑 `tests/screenshots.rs`；基准图按「机器」分目录，CI 只比自己的。成本 M，等 C2 绿了再看值不值 |

### N · 导航寻路（主菜）

自写，零依赖（和剖析器、补间、本地化一样）。分三步，每步都能单独交付：

| 编号 | 内容 | 规模 | 算完的标准 |
|---|---|---|---|
| N1 | **网格寻路**：`knav` crate。2.5D 格子（每格可走 / 高度 / 代价），从高度图 + 物理射线烘出来（每格往下打一条射线，坡度和台阶高度按角色控制器的参数判）；A*（八方向、对角不切角）+ 视线拉直（沿格子做 Bresenham 检查删多余拐点） | M | 例子：地形上点一下，胶囊沿路走过去、绕开箱子、不走陡坡；测试：迷宫最短路、不可达返回 `None`、拉直后不穿墙 |
| N2 | **导航网格**：Recast 那套的简化版——体素化可走三角形 → 区域 → 轮廓 → 凸多边形；多边形图上 A* + 漏斗算法（funnel / string pulling） | L | 和 N1 同一个例子换成导航网格，路径更短更顺；`Scene::bake_navmesh(根节点, 参数)`；烘一次的耗时进剖析器。**N1 够用就先不做** |
| N3 | **避让**：多个代理互相让路（RVO2 的简化，或者简单的分离力） | M | 例子：二十个代理对穿一条走廊不卡死 |

接法：`knav` 只认三角形 / 高度，不认场景；`kscene` 里加一层 `Scene::bake_nav_grid` / `find_path`，和根运动、角色控制器同一层。
脚本侧 `self.findPath(target)` 返回点列。

不接第三方：Rust 里成熟的导航库要么绑 Bevy（`oxidized_navigation`），要么只做寻路不做烘焙（`landmass`），
都要再包一层；N1 本身几百行。真到 N2 再评估一次。

### I · 实例化

| 编号 | 内容 | 规模 | 算完的标准 |
|---|---|---|---|
| I1 | `Node::with_instances(Vec<Instance>)`：一个节点带 N 个局部变换（+ 可选逐实例颜色 / 一个 `vec4` 自定义量，在 `material_vertex` 里能读到）。剔除按整组包围盒，绘制时展开成连续的逐对象数据——合批那条路现成 | M | 例子：十万棵草 / 两万颗星不用拼大网格；`benches/render.rs` 加一组「1 万节点 vs 1 个节点 × 1 万实例」，后者 CPU 时间降一个数量级 |
| I2 | 逐实例剔除（大组按块分小组包围盒） | S | 只有 I1 的例子里看得出浪费再做 |
| I3 | 计算着色器直接写实例数据（`draw_indirect`） | L | 等有具体需要（GPU 粒子当网格画）再做 |

### S · 结构（不加功能，有空就做）

| 编号 | 内容 | 什么时候做 |
|---|---|---|
| S1 | 拆 `krender/src/lib.rs`：材质管线 / 资源上传 / 帧编码三块进模块 | I1 要动绘制项收集，先拆这块再做 I1 能少很多冲突 |
| S2 | 拆 `kscene`：物理同步、音频同步、流式加载各成 crate | 改动开始互相绊脚时 |
| S3 | 删各 crate 目录下单独编出来的 `target/`（`.gitignore` 的 `target/` 已经覆盖了，不会进仓库，只占盘） | 你点头后，随时 |

## 三、建议顺序

```
C1 定格式 ─→ C2 推一次 ─→（绿了）C3 截图进 CI（可选）
   │
   └─ 和 C2 等结果的同时：
      N1 网格寻路（M）──→ N3 避让（M）──→ N2 导航网格（L，N1 不够用时）
      S1 拆 krender（M）──→ I1 实例化（M）──→ I2 / I3 按需
```

**这一轮的里程碑**：CI 在两个平台上绿着；有一个「点地面、角色绕开障碍走过去」的例子；
十万个相同物体不用手拼大网格。

## 四、不做的（重申）

不做 ECS、编辑器、多图形后端抽象、自写布局；第三方库各关在一个 crate 里；纯 Rust 工具链（唯一例外是视频解码，关在特性后面）——
见 ROADMAP「定下来的取舍」。导航和实例化都是零依赖自写。
